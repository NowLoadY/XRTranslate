# Director CLI 与 Agent 架构

内置 Agent 和外部执行者通过同一套 Director 操作软件。工具由插件声明，
主框架只负责发现和分发，不解释媒体字幕、音频参数或其他插件的业务含义。

## 职责边界

| 模块 | 职责 |
| --- | --- |
| Director 与 CLI | 定义工具调用和结果，发现已启用的提供者，复用现有本机控制服务。 |
| 工具提供者 | 拥有操作说明、参数约束、业务校验及实现；UI 类操作复用现有处理函数。 |
| Agent 插件 | 持有应用生命周期内的全局对话和摘要，独立管理每次执行的目标、范围、预算及取消状态。 |
| 应用宿主 | 装配模型能力、推理调度、插件工具和 Avatar 信箱，不复制业务逻辑。 |

公共能力位于可独立构建的 [ui-director](../../crates/ui-director/README.md) 包。
核心提供工具契约、发现、分发与操作反馈；可选 egui 适配提供控件登记、执行、位置和绘制。
本项目仅保留业务提供者、页面路由、模型调度和 Avatar 集成，框架不依赖本项目。

项目沿用静态 Rust 插件与显式能力装配。插件通过 `ToolProvider::tools/call`
接入，注册集中在 `plugins::tool_providers`。CLI 使用应用可执行文件的
`--control` 入口，在图形和模型初始化前转发请求；不另起应用或脚本运行时。

普通页面操作直接复用共享 UI 提供者，插件不必再声明一套按钮、选项和回调。
只有需要文档查询、后台任务或事务等业务语义时，才增加插件自己的工具提供者。

依赖与生命周期遵循[插件架构](../plugin-architecture.md)，推理与上下文遵循
[提示词架构](../prompt-architecture.md)，组件登记遵循[UI 架构](../ui-architecture.md)。

## 操作协议

工具描述、参数 schema、只读属性和执行函数由同一个提供者维护。调用由工具名称
和参数组成，返回实际结果或明确错误；目录也是 Agent 和外部 CLI 的操作说明。

```sh
XRTranslate --control tools
XRTranslate --control tools media
XRTranslate --control describe ui.pages ui.page ui.read ui.set
XRTranslate --control call ui.pages '{}'
XRTranslate --control call ui.read '{"limit":20}'
```

- `tools.list` 未筛选时返回简短概览，按命名空间或关键词筛选时默认附带完整参数，
  避免发现后再逐一查询；`schemas` 可覆盖此默认值。已知名称用 `tools.describe` 精确查询。
  关键词按字面匹配；无结果时按命名空间浏览。提供者的说明应与界面用词对应。
  内置 Agent 使用同一目录实现，并且只能发现当前任务作用域允许的工具。
- `ui.pages` 直接使用侧栏导航登记，包含核心页面和已启用的插件页面。进入页面后按需
  查看控件、选项或 `ui.text` 的局部正文；长文档由所属插件提供分页查询。
- UI 动作由实际界面帧消费后才报告成功；排队不等于完成。取消或过期的动作不得迟到执行。
- 任务轮询统一在 `App::logic` 推进，与窗口绘制分开；遮挡、最小化时仍处理推理结果、
  插件任务和会话事件。UI 动作按需请求一次后台界面帧，继续由原有控件处理函数执行，
  不强制置顶窗口或持续重绘。
- 长任务返回可查询、可取消的普通工具调用，执行者不需了解插件内部任务类型。
- Agent 按“观察、操作、真实反馈、再决策”执行，每轮选择一个操作或结束。
  操作与结束互斥，错误反馈不能伪装成已执行的结果。
- 空作用域允许跨插件发现；非空作用域约束每次调用的对应字段。
  Agent 运行时，外部执行者先停止它再接管写操作，查询可并行。
- 本地 HTTP 直接接收与进程内相同的 `ToolCall`，没有旧命令别名或另一套写操作入口。
  录制脚本也调用同一工具目录；截图和定时帧保持独立的录制通道。
- 请求、返回内容和执行过程都有容量或时间边界。停止同时取消推理等待和待完成操作；
  应用不能保证撤回供应商已经受理的远端推理。

## 模型与上下文

模型能力区分翻译、指令编辑和通用对话；Agent 是本地执行器，不是更高一级的模型接口。
准入依据现有能力记录的 `supports_chat`，不依据供应商端点名称或一次 JSON 输出推断。
仅支持 `supports_ask` 的模型可继续承担指令编辑，不自动启用 Agent。

Agent 模型默认跟随翻译模型，也可独立引用同一模型库。选择、凭据、账号、运行时计划
和调度均复用现有系统；Agent 插件不保存密钥，也不建立自己的供应商连接。
后端按模型生命周期复用无状态指令适配器与 HTTP 连接池；跟随翻译时共用同一实例。
账号凭据仍由原有账号组件逐次提供，适配器不缓存对话历史。

一次推理只接收本地提供的消息，不自动延续远端会话。Agent 保存自身历史，普通翻译
按提示词管线的作用域维护上下文；二者不混用。适配层不追加远端会话标识，避免两端
重复累积历史。结构化输出和供应商消息阶段差异留在推理适配层。

Agent 插件持有唯一的对话上下文，运行状态只管理本次执行。Avatar、CLI 和插件发起的
任务都向同一段历史追加消息。完成或停止只结束执行，后续指令继续使用已有项目引用、
工具结果及摘要；不提供“新建对话”入口。空闲时收到指令会开始下一次执行并重置执行
预算，运行中补充则保留当前进度和范围。

系统规则、当前执行范围、命名空间概览和两个目录操作构成前缀；开始下一次执行时
更新这条系统消息，其余历史按原顺序保留。旧工具说明和旧范围不授予当前执行权限。
目标、用户补充要求、模型决策及实际反馈都作为普通历史追加，具体工具 schema 按需查询，
不维护另一份“已加载工具”状态。输入接近预算时只固定系统消息，用累计摘要替换它已
覆盖的旧消息，保留最新结果和未总结内容；不永久固定第一个任务，也不截断正文或 JSON。
预算来自模型配置，具体限额由代码管理。提示词缓存由供应商决定，未报告的用量不计为零。
推理日志记录消息数、耗时及供应商用量；压缩日志记录估算大小变化。Agent 步骤日志记录
工具名称、反馈到达和错误原因，便于后续任务覆盖环境快照后仍能定位调用过程。
请求准备、调度排队和 HTTP 耗时分别记录；流式请求的首数据块时间不等同于首个文本 token。
临时传输或服务器故障由推理层标记，Agent 延迟有限重试相同上下文，不追加失败的
模型消息或重放工具。登录、权限、额度和配置错误直接保留原因并停止执行。

运行中收到补充要求时直接追加到同一上下文，不另建消息队列或重置进度、作用域与预算。
已开始的工具先返回真实结果；尚未执行的模型决定若使用了旧历史，则连同旧摘要一起丢弃，
下一轮读取新要求。最新要求纳入原有进度摘要，未总结的补充消息在压缩时原样保留。

全局对话在应用退出后结束。本地环境快照保存目标、历史和进度供诊断；重启只读取上一
次执行的结果或中断状态，不恢复旧对话或自动续跑。
环境快照可能包含任务正文，不作为公开架构文档或测试报告提交。

## 媒体适配

媒体插件提供任务范围内的工作副本、版本检查、局部识别候选及提交／撤销。
原文、译文、合并、拆分和删除复用字幕时间线操作；任务设置与 UI 共用更新入口。
拆分一次接收各段原文和译文，完整校验后一起更新预览，不暴露尚未补译的中间结果。
音频试验复用现有解码、识别和翻译管线，并拥有独立的任务取消范围。
试验用于调查识别疑点；仅需修正译文时直接编辑。评价候选须先读取正文，不能用条数
代替质量判断；已有结果应复用，重复试验须有输入、设置变化或具体失败依据。
试验可按字幕或时间范围选取，包含尚无字幕的区间；采用候选时必须完整覆盖且不覆盖已变更的原条目。
工具区分当前任务设置与候选生成时的设置，并报告实际选中的输入音轨。

工作副本与正式字幕分开。新一轮优化仅续用与当前字幕和任务条件一致的工作副本，
否则从当前字幕重新建立。优化中的页面只读预览工作副本；提交时再次检查原字幕与
任务约束是否变化，并同步界面和文件。保存失败恢复原状态，撤销不得覆盖用户后来修改的内容。

疑点检查返回计数和位置，正文按需分页读取。读取入口支持文本搜索、时间范围以及
原始、当前和候选文档；不同分段按同一时间范围比较。试验状态只返回摘要与文档引用，
不把整段字幕塞入回执或固定提示词。
修改回执和操作记录包含受影响的字幕 ID 与时间范围，便于上下文压缩后只复核修改位置。

短句和相邻重复是复核提示，不是必须消除的错误。修改原文、删除内容或采用识别候选
需要上下文或音频依据；结构检查通过不代表翻译准确。模型能力不足时保留手动编辑、
过长提示和外部 CLI，不启用隐藏的替代 Agent 流程。

## 可见反馈与维护入口

点击应用内 Avatar 可展开指令输入框。弹出位置复用消息气泡的避让算法，输入期间
固定 Avatar 位置；回车提交，输入法确认不触发发送，收起保留草稿。
指令通过现有 Agent 入口启动通用任务；运行时仍可回车发送补充要求，也可明确停止任务。

公共控件和虚拟列表负责操作定位、滚动和当帧几何位置；Avatar 消费框架反馈绘制连线。
反馈同时描述读取、调用、等待、失败和真实内容变化。控件值在处理函数执行后的下一帧
核对，文档变化只在校验通过后发出；删除内容定位到仍存在的容器。信息短暂保留，不进入
CLI 回执或模型上下文。框架默认绘制可替换，组件自身的外观、布局与动画保持独立。
插件只提供稳定的组件或文档 ID，核心层不增加插件名称分支，也不强行切换用户页面。
Agent 根据任务决定导航：交互式项目编辑通常进入对应项目详情，查询和后台处理可保留
当前页面。打开工作副本不等于打开界面；通过通用 UI 工具导航并核验，列表的打开按钮
带有项目标题，便于准确定位，不增加专属导航协议。
常规按钮、选框、下拉框、折叠区和输入框由共享组件登记；特殊外观使用响应适配器，
把动作交回原有 `clicked`／`changed` 处理。翻译记录和全屏展示的可见正文同样可分页读取。

Agent 的用户说明与内部进度笔记分开。说明送入现有 Avatar 信箱，使用任务启动时的
界面语言；媒体优化成功启动后额外投递本地化开始提示，不依赖模型主动说话。
发言要求简短口语和纯文本，不使用 Markdown 或朗读内部标识。完整长消息由共用气泡
分页逐字展示，每页阅读停顿后清空继续；工具参数、回执和内部笔记不直接显示为气泡。
